Общие принципы пострения проекта:
1. Минимальные задержки без спайков
2. Простота и модульность скриптов
3. Step by stepр реализация
4. Исчерпывающие логирование каждого скрипта - каждый скрипт имеет отдельный лог файл

Ньюансы реализации:
1. Батчинг модулей MD OB FR по времени или командам 
2. Сдвиг между батчами каждого источника ?

Константы 
exchange - binance; bybit; okx; gate.io; bitget.
market - spot;futures
частоты опроса spread_monitor - раз в 300 мс 
заданное значение спреда(%) - 1.00%
Батчинг модулей MD OB FR по времени или командам - 250 мс или 100 команд 
Stale - если пара не обновлялась больше 360 секунд 
Время сбора истории - 60-80 минут 
Время записи снапшота - 3500 секунд
Время кулдауна spread monitor - 3600 секунд





Модуль dictionaries  - независимый модуль, создаёт списки для подписок на WebSocket и списки комбинаций(пересечение торговых пар между двух бирж по рынкам спот и фьючерс)
Процесс работы:
1. Получение всех торговых пар по споту и фьючерсам с биржи
2. Подписка на WS каждой биржи и каждого рынка, при получение цен помечать торговую пару как проверенную
3. Из проверенных пар составляются списки комбинаций
4. Из списка комбинаций составлять списки для подписок на WebSocket 
5. Создание списка source_id - каждой бирже присваивается свой id
6. Создание списка symbol_id - каждому символу присваевается свой id

Модуль MD - получение best bid ask с каждого источника, и запись в редис
В редис пишутся с ключем md:{exchange}:{market}:symbol , внутри ключа следующий хеш:
b - значение бид a - значение ask ts - время записи в редис

Модуль OB - получение order book с каждого источника и запись в редис
Уровень стакана - 10 уровней (10level)
В редис пишутся с ключем ob:{exchange}:{market}:symbol, внутри ключа следующий хеш:
b1 - цена bid уровень 1 
b1q - количество по цене на уровне 1 
b2 - цена bid уровень 2
b2q - количество по цене на уровне 2
И так далее вплоть до 10 уровня, аналогично для ask

Модуль FR - получение значения fanding для каждого символа фьючерсных источников 
В редис пишутся с ключем fr:{exchange}:futures:symbol , внутри ключа следующем хеш:
fr - значение фандинга
fr_ts - время уплаты фандинга/вредя до следующего фандинга 

Модуль истории - держит в памяти редис историю за последние 60 минут каждого ключа,
создаёт новые ключи формата 
md:hist:{exchange}:{market}:symbol:{chunk}
ob:hist:{exchange}:{market}:symbol:{chunk}
fr:hist:{exchange}:futures:symbol:{chunk}
Тип ключе - list , где построчно дублируются уже получение строки, согласно заранее утвержденным стандарту записи, который строится по следующей логике
модуль MD - имеет значение для каждого ключа как b - значение; a - значение ; ts - значение
мы пишем как лист по строчно 
значение b,значение a,значение ts
Система чанков в модули истории:
Каждый чанк пишется 20 минут, при записи 5 чанка удаляем 1 чанка, при записи 6 чанка удаляем 2 чанк и так далее 
hist:config - ключ в редис содержащий информацию о активных чанках, и о периоде охвата каждого чанка,

Stale monitor - получается информации о каждом ключе модуля MD , и сравнивает текущее время, в случае если разница по времени выше заданного значения пишет в лог файл ключ и время stale

redis monitor - пишет лог файл о здоровье редис

Spread_monitor - сканирует пары для поиска спреда, списки сканирования берутся по спискам комбинаций
формула спреда - (ask_spot - bid_futures) / ask_spot) * 100 
Опрос раз в 300 мс 
В случаи если спред выше заданного значения запись в лог файл в формате - 
spot_exch,fut_exch,symbol,ask_spot,bid_futures,spread_pct,ts
binance,bybit,BTCUSDT,45000.10,45676.35,1.5023,1741234567890 
Пишется в signal/signal.csv
После получения сигнала не повторяет его в течение 3600 секунд, по конкретному символу конкретного направления
